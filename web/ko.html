어떻게 동작하나요

에이전트는 판단하고, 돈이 움직일 수 있는 범위는 컨트랙트가 정합니다.

  1. 브리프 → 계획. 오너가 평이한 문장으로 요청을 쓰면 Foreman이 작업 범위, 마일스톤, 승인 기준, 금액을 초안으로 만들고 계획 전체의 해시(termsHash)를 남깁니다. 오너가 확인하면 계획이 확정됩니다.
  2. USDC 에스크로. 오너가 ForemanPolicy를 통해 마일스톤 대금을 USDC로 에스크로(Stagepay)에 예치합니다. 에이전트는 대금을 직접 들고 있지 않습니다.
  3. 납품물 제출. 프리랜서가 풀 리퀘스트나 URL을 메모로 붙여 마일스톤을 제출하면 검수 기간이 시작됩니다.
  4. 자동 검수. 에이전트가 가격이 매겨진 도구를 호출할 때마다 소액의 USDC를 내고 증거를 모아, 승인 기준을 하나씩 확인합니다. 판단 근거의 해시는 온체인에 기록됩니다.
  5. 승인 시 지급. 기준을 모두 충족하면 에이전트가 승인하고, 컨트랙트가 한도를 확인한 뒤 프리랜서에게 즉시 USDC를 지급합니다. 기준이 빠지면 구체적인 수정 요청을 보내고, 한도를 넘는 금액은 오너의 공동 서명을 기다립니다.

계약이 강제하는 한도

한도는 프롬프트가 아니라 온체인 컨트랙트인 ForemanPolicy에 있습니다. 그래서 모델이 혼동하거나 탈취되더라도 오너가 허용한 금액 이상은 움직일 수 없습니다.

  • 에이전트는 작업 대금을 직접 보유하지 않습니다. 대금은 에스크로가 보관하고, 정책 컨트랙트가 에스크로의 유일한 클라이언트입니다

    막아 주는 것: 탈취된 에이전트 키로 자금이 빠져나가는 일

    강제 주체: ForemanPolicy + Stagepay
  • 프리랜서가 제출한 마일스톤에 대해서만 대금이 움직입니다

    막아 주는 것: 납품되지 않은 작업에 대금을 지급하는 일

    강제 주체: ForemanPolicy (NotSubmitted)
  • 마일스톤당 자동 승인 한도

    막아 주는 것: 잘못된 판단 한 번으로 큰 금액의 마일스톤이 지급되는 일

    강제 주체: ForemanPolicy (OverAutoApproveCap)
  • 모든 작업을 합산한 일일 지급 한도

    막아 주는 것: 짧은 시간 안에 같은 실수가 반복되는 일

    강제 주체: ForemanPolicy (OverDailyCap)
  • 한도 초과 시 → agentEscalate, 이어서 오너의 ownerCosign

    막아 주는 것: 사람의 확인 없이 이뤄지는 고액 지급

    강제 주체: ForemanPolicy (NotEscalated)
  • 킬 스위치 setPaused(true)가 에이전트의 모든 동작을 멈춥니다. 오너 전용 함수는 계속 동작합니다

    막아 주는 것: 오작동하는 에이전트를 즉시 정지

    강제 주체: ForemanPolicy (IsPaused)
  • 도구 지출은 선불 채널로 상한을 두며, 에이전트가 이 채널에서 쓰는 키는 자금이 없는 세션 키입니다

    막아 주는 것: 걷잡을 수 없이 불어나는 도구 비용. 키가 유출돼도 손실은 최대 채널 잔액

    강제 주체: Tollgate
  • 마일스톤당 수정 요청은 최대 3회이며, 아무도 응답하지 않으면 검수 기간이 지난 뒤 프리랜서가 대금을 직접 받아 갈 수 있습니다

    막아 주는 것: 에이전트(또는 오너)가 완성된 작업을 볼모로 잡는 일

    강제 주체: Stagepay

에이전트의 코드도 실행하기 전에 한도를 미리 확인하지만, 최종 권한은 항상 컨트랙트에 있습니다.
